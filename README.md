# I-Beam: запуск сайта по шагам

Сайт состоит из обычных файлов (HTML, CSS, JS), собирать ничего не нужно.
Данные, вход, фото и права хранит бесплатный Supabase, сайт показывает бесплатный Vercel.

Что внутри:
- `index.html`, `boats.html`, `best.html`, `login.html`, `admin.html`: страницы
- `js/config.js`: сюда вставляются ключи Supabase
- `supabase/1_schema.sql`, `2_schedule.sql`, `3_make_owner.sql`: база данных

## Шаг 1. Создай проект в Supabase

1. Зайди на supabase.com, нажми Start your project и войди через GitHub.
2. New project: придумай название (например `ibeam`), пароль базы (сохрани его) и выбери ближайший регион.
3. Подожди 1-2 минуты, пока проект создастся.

## Шаг 2. Загрузи базу данных

1. В Supabase открой SQL Editor, затем New query.
2. Открой файл `supabase/1_schema.sql`, скопируй всё, вставь и нажми Run. Должно появиться Success.
3. Новый запрос: вставь `supabase/2_schedule.sql` и нажми Run. Это расписание: каждое воскресенье в 06:00 по Москве сайт фиксирует топ-5. Если будет ошибка про pg_cron, включи его в Database, затем Extensions, и запусти файл ещё раз.

## Шаг 3. Вставь ключи в сайт

1. В Supabase: Project Settings, затем API.
2. Скопируй Project URL и ключ anon public.
3. Открой `js/config.js` и замени `YOUR_SUPABASE_URL` и `YOUR_SUPABASE_ANON_KEY`. Эти два значения публичные по задумке, защиту дают правила доступа из шага 2. Ключ service_role никуда вставлять нельзя.
4. В `SUPPORT_EMAIL` впиши почту поддержки (она появится в подвале сайта).

## Шаг 4. Выложи сайт

1. Зарегистрируйся на github.com, создай репозиторий (кнопка New), назови `ibeam-site`.
2. Add file, затем Upload files: перетащи туда все файлы и папки из архива (содержимое папки `ibeam-site`) и нажми Commit.
3. Зайди на vercel.com через GitHub (тариф Hobby бесплатный). Add New, затем Project, выбери репозиторий.
4. В Framework Preset выбери Other, ничего больше не меняй, нажми Deploy.
5. Через минуту сайт откроется по адресу вида `ibeam-site.vercel.app`. Красивый адрес: Settings, затем Domains, например `ibeam.vercel.app`, если имя свободно.

## Шаг 5. Подскажи Supabase адрес сайта

Supabase, Authentication, URL Configuration:
- Site URL: адрес твоего сайта, например `https://ibeam.vercel.app`
- Redirect URLs: добавь `https://ibeam.vercel.app/**`

Без этого ссылки из писем (подтверждение почты, смена пароля) и вход через Google будут вести не туда.

Про подтверждение почты: по умолчанию новый пользователь получает письмо и должен нажать на ссылку. Встроенная отправка Supabase ограничена несколькими письмами в час. Для первых тестов можно выключить: Authentication, Providers, Email, отключить Confirm email. Перед открытием сайта людям лучше включить обратно.

## Шаг 6. Выдай себе права владельца

1. Открой свой сайт и зарегистрируйся (кнопка «Регистрация»). Если включено подтверждение почты, подтверди её.
2. В Supabase открой SQL Editor и вставь `supabase/3_make_owner.sql`. Замени `ТВОЯ_ПОЧТА@gmail.com` на почту, с которой регистрировался, и нажми Run. Должна вернуться одна строка с `is_owner = true`.
3. Обнови сайт. В шапке появится кнопка «Админ».

Почему так: владельца нельзя назначить с самого сайта, иначе первый же зашедший смог бы забрать себе власть. Этот шаг делается один раз.

## Шаг 7. Назначай админов

Админ, затем Пользователи. Найди человека по нику и нажми «Сделать админом». У него в шапке появится «Админ». Только владелец может назначать и снимать админов. Обычные админы выбирают лучшую работу, модерируют и блокируют нарушителей, но почты пользователей не видят (кроме почт финалистов недели).

## Вход через Google (по желанию)

1. console.cloud.google.com: создай проект, затем APIs and Services, затем Credentials, затем Create credentials, затем OAuth client ID, тип Web application.
2. В Authorized redirect URIs впиши `https://<код-проекта>.supabase.co/auth/v1/callback` (код проекта виден в Project URL Supabase).
3. Скопируй Client ID и Client secret в Supabase: Authentication, Providers, Google, включи и сохрани.

Пока Google не настроен, кнопка покажет понятное сообщение, остальной вход работает.

## Как работает неделя

- Участники выкладывают фото, остальные ставят оценки 1-10 и пишут комментарии.
- Первые 3 фото нового участника ждут твоего одобрения (админ), дальше публикуются сразу. Если на фото пожаловались 3 человека, оно скрывается до проверки.
- Каждое воскресенье в 06:00 по Москве сайт фиксирует топ-5: берутся лодки за последние 7 дней, у которых не меньше 3 оценок. Авторам приходит уведомление «Выбираем лучшую работу».
- В Админ, затем «Лучшая работа недели» ты видишь пятёрку с почтами авторов, выбираешь одну, и она получает рамку на сайте и попадает на «Лучшие работы». Если автор не отвечает, нажми «Не ответил, выбрать другую».
- Чтобы проверить всё сразу, не дожидаясь воскресенья: поставь лодкам оценки с нескольких аккаунтов и нажми «Подвести итоги сейчас (проверка)» в админке. Все числа (3 жалобы, 3 оценки и т.д.) меняются в блоке «Автоматика».

## Что важно знать

- Автоматической проверки картинок нейросетью нет: защита построена на проверке первых фото, жалобах, лимите 5 фото в сутки, и фото сжимается на устройстве (заодно убираются данные съёмки). Сервис автопроверки (например, Sightengine) можно добавить позже.
- Адреса фото публичные и трудноугадываемые. Даже фото на проверке откроется по прямой ссылке, но найти её нельзя.
- Уведомления приходят на сайте (кнопка «Уведомления»), не на почту. Письма победителю ты пишешь сам с почты из админки.
- Раздел «Build a Boat» (схемы и туториалы) на главной пока заглушка со словом «Скоро»: его нужно наполнять твоим содержимым.
- На бесплатном Supabase проект, которым неделю никто не пользуется, ставится на паузу. Он включается одной кнопкой в панели Supabase.
